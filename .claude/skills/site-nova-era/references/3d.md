# 3D: gerar, modelar e mostrar no site

3D só quando **é o momento-assinatura ou mostra o produto melhor que foto** (produto físico, embalagem, peça, maquete, moeda/símbolo da marca). Nunca 3D decorativo girando sem motivo.

## Meios de obter o modelo (do mais barato ao mais caro)

| Meio | Custo | Bom para | Como |
|---|---|---|---|
| **Procedural no Three.js** | grátis | formas da marca (moeda, anel, símbolo extrudado, knot, partículas) | `tres.js` com `data-shape`, ou geometria própria (ExtrudeGeometry a partir do SVG do logo com SVGLoader) |
| **Higgsfield 3D Jutsu** | **grátis** para montar, editar e renderizar a cena hospedada (só render com IA cobra) | cenas e objetos montados por Python estilo Blender, exporta GLB | carregar `get_preset_instructions { preset: "/3d-jutsu" }` → `scene_builder_3d_create_project` → `scene_builder_3d_query_python`/`run_python` → `scene_builder_3d_get_glb` |
| **Poly Haven** (`api.polyhaven.com`) | grátis, CC0 | modelos, texturas PBR e HDRIs de ambiente | `GET https://api.polyhaven.com/assets?t=models` → `GET /files/<id>` → baixar o GLB/gltf e HDRI |
| **Khronos glTF Sample Assets** | grátis | testes de pipeline | `cdn.jsdelivr.net/gh/KhronosGroup/glTF-Sample-Assets@main/Models/<Nome>/glTF-Binary/<Nome>.glb` |
| **Blender MCP** | grátis | modelagem real, com o Blender aberto **no computador do usuário** | só com máquina do usuário conectada (`request_computer_folder`); exportar GLB |
| **Imagem → 3D (muapi)** | pago (saldo muapi) | produto do cliente a partir de foto(s) | `tripo3d-h31-image-to-3d`, `tripo3d-h31-multiview-to-3d`, `meshy-6-image-to-3d` (`target_polycount` 10k a 30k), `meshy-v7-*`; texto → 3D: `tripo3d-*-text-to-3d`, `meshy-6-text-to-3d` |
| **Imagem → 3D (Higgsfield)** | pago | idem, com rig e animação | `generate_3d` (`image_to_3d`, `multi_image_to_3d` com 2 a 4 vistas, `sam_3_3d`); sempre `get_cost: true` antes |
| **Sketchfab** | chave | modelos prontos com licença | API exige token (salvar nas configurações do ambiente); conferir licença de cada modelo |

Regra de imagem → 3D: foto de produto com fundo limpo (rodar `ai-background-remover` antes), luz difusa, 2 a 4 vistas quando possível. Gerar com qualidade "standard" primeiro; "detailed" só no modelo aprovado.

## Pipeline obrigatório

1. Obter o GLB.
2. Otimizar: `bash templates/otimizar-3d.sh modelo.glb assets/3d/modelo.glb 1024 0.75` (meshopt + texturas WebP + simplificação; testado: 3,7 MB → 508 KB).
   Metas: hero ≤ 1,5 MB, secundário ≤ 500 KB, ≤ 100k triângulos, texturas ≤ 2048 (1024 no mobile).
3. Poster: renderizar o bloco `.tres` e salvar screenshot do elemento como `poster.webp` (Playwright `locator('.tres').screenshot()`), depois `otimizar-imagens.sh`. O poster aparece até o 3D ficar pronto e é o fallback.
4. Colocar no site com `templates/base/tres.js`.
5. Testar: com e sem reduced motion, 390 e 1440, e conferir que o LCP não piorou (`auditar-site.js`).

## Mostrar no site

### Opção A: `tres.js` (padrão da skill, Three.js 0.187.0)
- Import map no `<head>` (já no `templates/base/index.html`).
- `<div class="tres" data-tres data-src="assets/3d/modelo.glb" data-scroll="rotate" data-idle="0.15" data-tilt role="img" aria-label="...">` + `<img class="tres__poster">`.
- O Three só é baixado quando o bloco chega a 300 px da tela. Sem WebGL, com `saveData` ou com erro: fica o poster.
- Para a renderização fora da tela e na aba oculta; DPR ≤ 1,75; reduced motion: um quadro parado.
- Atributos: `data-scroll="rotate"` (gira com o scroll), `data-idle` (rad/s), `data-tilt` (segue o mouse), `data-exposure`, `data-fit`, `data-shape` (sem modelo).

### Opção B: `<model-viewer>` (Google, 4.4.0)
Quando o cliente quer "girar o produto" e **ver em AR no celular** sem código:
```html
<script type="module" src="https://cdn.jsdelivr.net/npm/@google/model-viewer@4.4.0/dist/model-viewer.min.js"></script>
<model-viewer src="assets/3d/produto.glb" poster="assets/3d/poster.webp" alt="..." camera-controls touch-action="pan-y"
  auto-rotate rotation-per-second="12deg" ar ar-modes="webxr scene-viewer quick-look" loading="lazy" reveal="interaction"></model-viewer>
```

### Opção C: cena com scroll (momento-assinatura 3D)
`tres.js` dentro de um `[data-pin]` (motion.js): ler `--p` do pin e mapear para câmera/rotação/explosão de peças. Uma só por página. Manter a lista de etapas em HTML (acessível e indexável).

### Shader/fundo
Gradiente vivo, grão, ondas: shader em `<canvas>` leve ou `create_shader` do Figma para explorar o visual. Mesmas regras: pausa fora da tela, DPR baixo, reduced motion parado.

## Erros que matam a performance

- Carregar Three.js na primeira dobra sem necessidade (use o import dinâmico do `tres.js`).
- GLB sem compressão, texturas 4K, HDRI de 20 MB (use `RoomEnvironment` ou HDRI 1k).
- Vários canvases WebGL na mesma página (reaproveite um).
- Sombras em tempo real e pós-processamento no mobile.
